# Smit Gym — אפיון מודול מאמנים (Coach Module)

> מסמך אפיון: איך Smit Gym הופכת ממערכת למתאמן עצמאי למערכת שגם **מאמן** יכול לנהל בה מתאמנים.
> נכתב יולי 2026. סטטוס: **אפיון — טרם נבנה.**

---

## 1. התמונה בגדול

היום האפליקציה היא **חד-משתמשית**: כל אחד מייצר לעצמו תוכנית ותפריט.
המודול החדש מוסיף **תפקיד שני** — מאמן, שמנהל עד ~10 מתאמנים.

**ההחלטה המרכזית שאני ממליץ עליה: אפליקציה אחת, שני תפקידים.**

| | אפליקציה אחת (מומלץ ✅) | שתי אפליקציות נפרדות |
|---|---|---|
| התקנה | המתאמן מתקין פעם אחת | המאמן צריך אפליקציה שנייה |
| מאמן שגם מתאמן | עובד טבעי — מחליף תצוגה | צריך שני חשבונות |
| תחזוקה | קוד אחד | כפול |
| חנות אפליקציות | רישום אחד | שני רישומים |

מאמן = משתמש רגיל עם דגל `isCoach`. בפרופיל שלו מופיע מתג **"מצב מאמן"** שמחליף בין
"האימונים שלי" לבין "המתאמנים שלי".

---

## 2. איך מאמן ומתאמן מתחברים

**קוד הזמנה** — הדרך הפשוטה והבטוחה ביותר (בלי לחפש אנשים לפי מייל, בלי ספאם):

```
המאמן                                    המתאמן
  │                                         │
  ├─ "הוסף מתאמן" → נוצר קוד: SMIT-4K7Q     │
  │  (תקף 7 ימים, לשימוש חד-פעמי)           │
  │                                         │
  ├──────── שולח בוואטסאפ ─────────────────▶│
  │                                         │
  │                    פרופיל → "יש לי מאמן" → מקליד קוד
  │                                         │
  │                    ┌────────────────────┴─────────────┐
  │                    │ מסך אישור:                       │
  │                    │ "אריאל מבקש לאמן אותך"           │
  │                    │ הוא יוכל: ✓ לערוך אימונים        │
  │                    │           ✓ לערוך תפריט          │
  │                    │           ✓ לראות משקל והתקדמות  │
  │                    │        [אשר]  [דחה]              │
  │                    └────────────────────┬─────────────┘
  │                                         │
  ◀──────── הקשר נוצר ─────────────────────┤
```

**עקרון מנחה: המתאמן תמיד בשליטה.** הוא מאשר בכניסה, רואה בדיוק מה המאמן יכול לעשות,
ויכול **לנתק את הקשר בכל רגע** מהפרופיל. בלי אישור — למאמן אין שום גישה.

---

## 3. מה מאמן יכול לעשות (מטריצת הרשאות)

המתאמן מאשר כל קטגוריה בנפרד בעת החיבור, וניתן לשנות אחר כך.

| הרשאה | מה זה נותן למאמן | ברירת מחדל |
|-------|-------------------|-------------|
| `workouts` | לראות **ולערוך** את תוכנית האימונים, לראות סטים שבוצעו | ✅ פעיל |
| `nutrition` | לראות **ולערוך** את התפריט והיעדים הקלוריים | ✅ פעיל |
| `metrics` | לראות משקל, BMI, היסטוריית שקילות, מים, צעדים | ✅ פעיל |
| `notes` | לכתוב הערות אישיות שהמתאמן רואה | ✅ פעיל |

**מה מאמן לעולם לא יכול:** לראות את הסיסמה, למחוק את החשבון, לראות את הפיד/הודעות
הפרטיות של המתאמן, או לגשת למתאמנים של מאמן אחר.

## 4. מסכים — צד המאמן

### 4.1 דשבורד מאמן (מסך הבית במצב מאמן)

הרעיון: **לזהות תוך 3 שניות מי צריך תשומת לב**.

```
┌──────────────────────────────────────────┐
│  המתאמנים שלי                      [+]   │
│  10 מתאמנים · 7 התאמנו השבוע             │
├──────────────────────────────────────────┤
│  🔴 צריכים תשומת לב                       │
│  ┌────────────────────────────────────┐  │
│  │ [תמונה] דני כהן                     │  │
│  │ לא התאמן 6 ימים · עלה 1.2 ק״ג       │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │ [תמונה] מאיה לוי                    │  │
│  │ סיימה את התוכנית — צריך תוכנית חדשה│  │
│  └────────────────────────────────────┘  │
├──────────────────────────────────────────┤
│  ✅ בכיוון טוב                            │
│  ┌────────────────────────────────────┐  │
│  │ [תמונה] יוסי · 4/5 אימונים · -0.8ק״ג│ │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**דגלים אוטומטיים** שמעלים מתאמן ל"צריכים תשומת לב":
- לא התאמן ≥ 5 ימים
- סטה מהמשקל בכיוון ההפוך למטרה ≥ 1 ק״ג בשבועיים
- סיים את כל אימוני התוכנית
- לא עדכן משקל ≥ 14 יום

### 4.2 כרטיס מתאמן

ארבע לשוניות: **סקירה · אימונים · תזונה · התקדמות**

- **סקירה** — פרטים אישיים, מטרה, יעד קלורי, הערות המאמן
- **אימונים** — התוכנית הנוכחית + מה בוצע בפועל (סטים, משקלים) + כפתור **"ערוך תוכנית"**
- **תזונה** — התפריט הנוכחי + **"ערוך תפריט"**
- **התקדמות** — גרף משקל, אימונים לשבוע, נפח אימון (טונאז׳) לאורך זמן

### 4.3 עורך תוכנית / תפריט

**חוסך פיתוח:** אלה בדיוק המסכים הקיימים (`WorkoutScreen` / `NutritionScreen`), רק
שכותבים ל־`traineeUid` במקום למשתמש הנוכחי. הוספה: פס עליון בולט —
> ✏️ אתה עורך את התוכנית של **דני כהן** · [שמור ושלח] [בטל]

בשמירה המתאמן מקבל התראה: *"המאמן עדכן לך את תוכנית האימונים"*.

---

## 5. מסכים — צד המתאמן (מה משתנה)

מינימלי בכוונה — לא רוצים להעמיס על מי שמתאמן לבד:

1. **כרטיס "המאמן שלי"** במסך הבית — תמונה, שם, הערה אחרונה, כפתור פנייה
2. **תג "עודכן ע״י המאמן"** על תוכנית/תפריט שהמאמן שינה, עם תאריך
3. **בפרופיל** — קטע "המאמן שלי": מה הוא רואה, וכפתור **"נתק מאמן"**
4. **התראה** כשהמאמן מעדכן משהו

מתאמן בלי מאמן — האפליקציה נראית בדיוק כמו היום.

## 6. מודל נתונים (Firestore)

```
users/{uid}
  ├─ ...קיים...
  ├─ isCoach: bool               # האם המשתמש גם מאמן
  └─ coachUid: string | null     # מי מאמן אותי (משוכפל לצורך כללי אבטחה)

coachProfiles/{coachUid}         # הפרופיל הציבורי של המאמן
  ├─ name, photo, gymName, bio, certifications
  └─ traineeCount

coachLinks/{linkId}              # הקשר מאמן↔מתאמן
  ├─ coachUid, traineeUid
  ├─ status: 'pending' | 'active' | 'ended'
  ├─ permissions: { workouts, nutrition, metrics, notes }
  └─ createdAt, acceptedAt, endedAt

inviteCodes/{code}               # קוד הזמנה חד-פעמי
  ├─ coachUid
  ├─ expiresAt                   # 7 ימים
  └─ usedBy: uid | null

users/{traineeUid}/coachPlans/{planId}    # מה שהמאמן כותב
  ├─ type: 'workout' | 'meal'
  ├─ payload                     # התוכנית עצמה
  ├─ createdBy: coachUid
  └─ createdAt, seenByTrainee: bool

users/{traineeUid}/coachNotes/{noteId}
  └─ text, createdBy, createdAt
```

### למה תת-קולקציה `coachPlans` ולא כתיבה ישירה למסמך המשתמש?

זו **הנקודה הקריטית לאבטחה**. אם המאמן היה כותב ישירות ל־`users/{uid}`, היינו צריכים
כלל שמאפשר לו לכתוב לשדות מסוימים בלבד — שביר ומסוכן. בתת-קולקציה נפרדת הכלל פשוט
וחד-משמעי:

```javascript
function myCoachIs(userId) {
  return request.auth != null &&
    get(/databases/$(database)/documents/users/$(userId)).data.coachUid == request.auth.uid;
}

match /users/{userId}/coachPlans/{planId} {
  allow read:  if request.auth.uid == userId || myCoachIs(userId);
  allow write: if myCoachIs(userId);      // המאמן כותב, המתאמן רק קורא
}
```

הנתונים הפרטיים של המתאמן (`users/{uid}` עצמו) נשארים **סגורים לחלוטין** למאמן, חוץ
משדות שנחשוף במפורש.

## 7. שלבי בנייה מומלצים

| שלב | מה נבנה | ערך למשתמש | היקף |
|-----|---------|-------------|------|
| **1** | קשר מאמן↔מתאמן: קוד הזמנה, אישור, ניתוק + דשבורד **לקריאה בלבד** | מאמן רואה איך המתאמנים מתקדמים | ~יומיים |
| **2** | עריכת תוכנית אימונים ע״י המאמן + התראה | הערך המרכזי | ~יום-יומיים |
| **3** | עריכת תפריט + הערות מאמן | חבילה מלאה | ~יום |
| **4** | דגלי "צריך תשומת לב", גרפי התקדמות מתקדמים | חוסך למאמן זמן | ~יום |
| **5** | מנוי למאמנים (תשלום לפי מספר מתאמנים) | מודל הכנסה | נפרד |

**המלצה:** לעצור אחרי שלב 2 ולתת את זה למאמן אמיתי אחד לבדיקה, לפני שממשיכים.

## 8. החלטות שצריך לקבל לפני בנייה

1. **המאמן עורך ישירות, או מציע והמתאמן מאשר?**
   המלצה: **עורך ישירות** — זה מה שמצופה ממאמן, והמתאמן רואה תג "עודכן ע״י המאמן".
   (אם מדובר בקהל שרגיש לשליטה, אפשר "הצעה + אישור".)

2. **האם מאמן יכול להיות גם מתאמן?**
   המלצה: **כן** — מתג בפרופיל. רוב המאמנים מתאמנים בעצמם.

3. **מודל תשלום** — המאמן משלם לפי מספר מתאמנים? המתאמן משלם? חינם בהתחלה?

4. **מה קורה כשמנתקים קשר** — התוכנית שהמאמן בנה נשארת אצל המתאמן (המלצה: כן, נשארת).

## 9. השפעה על מה שקיים

- `profileShareService` הקיים (קישור שיתוף עם snapshot ותפוגה) **נשאר** — הוא מתאים
  ל"תן הצצה חד-פעמית למאמן/חבר". מודול המאמנים הוא קשר **חי ודו-כיווני**, שכבה נפרדת.
- `workoutEngine` / `mealPlanGenerator` — ללא שינוי, רק נקראים עם מזהה מתאמן אחר.
- `WorkoutScreen` / `NutritionScreen` — צריכים לקבל `traineeUid` אופציונלי במקום להניח
  שהמשתמש הנוכחי הוא הבעלים. זה השינוי המבני היחיד המשמעותי.
